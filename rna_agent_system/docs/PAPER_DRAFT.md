## Abstract

RNA therapeutics — mRNA vaccines, small interfering RNAs, guide RNAs, antisense oligonucleotides and aptamers — are designed by chaining dozens of specialized computational tools, and this orchestration remains expert manual work. Language-model agents could automate it, but an agent that consumes predictive scores at face value and narrates its own results can fail in ways that are hard to detect. Here we present RNADesignAgent, a tool-first agent for eleven RNA design workflows in which every predictive oracle is profiled on curated anchor sets before use, every action and claim then passes deterministic gates checked against this empirical self-model, and every tool call is recorded to an append-only audit trail. On RNADesign-210, a 210-task benchmark spanning all eleven workflows, the platform completes every task with biologically valid outputs. Profiling revealed that three deployed structure oracles retained none of their presumed screening, ranking or docking power for RNA–protein aptamers (0 of 27 oracle–target cells showed reliable screening or ranking power, and native poses ranked top-1 in 0 of 19 docking complexes), while an expression oracle was decisively certified on measured ribosome-load anchors. Gating eliminated false-positive claims on both flagship task families (gated 0% and 8.3% versus ungated 54.5% and 38.9%, both arms re-run at the 45-task reset scale) while retaining 80% and 100% of true positives — the aptamer-side losses decompose into over-conservative claim suppression, correctly abstained false claims and by-design unverifiable lucky picks — and budget-matched controls retired our own earlier coordination claims. Generation-layer constraint navigation (GenNav) delivered pre-registered multi-constraint design profiles where a rule-based executor failed — decisively on mRNA (McNemar P = 1.9 × 10⁻⁹) and, at equal budget, on aptamers (discordant cells 14:3, P = 0.013). Calibrated agency makes agentic science auditable.

## Introduction

RNA has become a therapeutic modality of central importance. mRNA vaccines reached billions of doses within a year of a pandemic onset; small interfering RNAs, guide RNAs, antisense oligonucleotides and aptamers hold approved indications or are in late-stage trials across metabolic, cardiovascular and infectious disease. Every one of these modalities begins with a design problem that is genuinely multi-objective: a messenger RNA must balance codon optimality against secondary-structure stability, translation-initiation context and UTR-mediated regulation; an aptamer must fold, bind and remain specific; every candidate must additionally satisfy manufacturability and safety constraints.

The field has answered with a constellation of specialized computational tools — sequence optimizers, structure predictors, expression and stability models, off-target scanners — each excellent within its remit and silent outside it. No single tool spans the pipeline. Chaining them into a coherent design campaign remains expert manual work that can take days per target, and the number of tools a designer must master keeps growing. This mismatch between tool abundance and expert bandwidth is the bottleneck we address.

Large-language-model (LLM) agents are a natural candidate to automate this orchestration, and recent systems have demonstrated agentic tool use across the sciences — in chemistry (ChemCrow, Coscientist), protein design (ProtAgents, the Virtual Lab), gene-editing experiment planning (CRISPR-GPT) and general biomedical data analysis (BioMni). None of these addresses RNA design: BioMni, the largest open biomedical tool environment, contains no RNA sequence-design capability (verified against its repository at commit 400c1f3 — the only RNA-specific tools are a ViennaRNA RNAfold wrapper and a codon-substitution utility that requires a user-supplied codon-usage table, and its CRISPR tasks select perturbation genes and retrieve precomputed guides rather than designing them), while concurrent preprints on agentic mRNA design and RNA–ligand modelling remain single-workflow and without released code. However, deploying such agents over real predictive tooling raises a problem that current systems do not address: the agent inherits every assumption of every tool it calls, and it narrates its own results in natural language. We reasoned that three recurrent failure modes follow from this structure, and that measuring them is a prerequisite for fixing them. First, **uncalibrated tool trust**: agents consume predictive scores at face value, without validating whether a given model has demonstrated power for the task, target family or molecular regime at hand. Second, **claim overreach**: because agents draft their own reports, statements can drift beyond what the underlying measurements support, and are difficult to audit after the fact. Third, **confounded improvement**: agent strategies typically also *generate more candidates*, so an apparent optimization gain may be nothing more than a larger sampling budget. None of the existing scientific agents profiles its deployed predictors before relying on them, gates its own claims against that evidence, or matches generation budgets when comparing strategies.

Here we present RNADesignAgent, a tool-first, calibrated agent for RNA design (Fig. 1). The platform wraps 41 scientific tools behind 21 local microservices and composes them into eleven deterministic domain workflows; a multi-agent execution layer orchestrates, reviews and synthesizes, and the language model never writes a sequence — every molecule is produced by a validated generator, which makes every design decision traceable to an auditable tool call. Two mechanisms then supply the calibration. **Capability-layer evidence gating (CapGate)** profiles each (oracle, task type, target family) combination on assertion-curated anchor sets before use, and feeds the resulting capability map to two deterministic gates: a DecisionGate that forbids actions whose evidentiary basis is absent, and a ClaimGate that degrades or suppresses natural-language claims exceeding the evidence. **Generation-layer constraint navigation (GenNav)** makes the agent earn its keep where a single tool cannot: delivering batches of candidates that jointly satisfy pre-registered, multi-constraint design profiles, by navigating the generator's own control space under a matched budget. Every comparative claim in this paper follows a pre-registered, budget-matched protocol.

Our contributions are:

1. **A tool-first RNA design platform with deterministic multi-agent execution and full-pipeline auditability.** Eleven domain workflows composed from 41 scientific tools exposed as 21 local microservices, with fixed generate–evaluate–score–rank pipelines, interface-locked contracts, service pre-flight, and an append-only audit trail that records every tool call — parameters, results, timings and gate decisions — making every design decision traceable and every campaign reproducible from its trail. The multi-agent layer — pipeline scheduling, per-workflow specialists, bounded coordination, advisory quality review and synthesis — is presented with the contribution of each agent measured rather than asserted: quality review is shown to be advisory (19/19 tasks succeed with and without it), the coordination loop was removed after its headline benefit was falsified under budget matching (budget-matched serial generation proved statistically indistinguishable), and mechanized ranking reduces LLM involvement to tie arbitration with perfect rank agreement (Kendall τ = 1.0).

2. **RNADesign-210, a process-aware benchmark for RNA design agents.** Two hundred and ten curated tasks spanning all eleven workflows, with deterministic success criteria, designed null models (wild-type versus random-synonymous controls) and literature anchors (vaccine-grade mRNA sequences, known aptamers, IRES panels, measured ribosome-load sets). The platform completes 210/210 tasks, and the benchmark doubles as a continuous regression suite for the system itself. All task definitions, expected outputs and null models are released with the platform.

3. **Capability-layer evidence gating (CapGate).** An anchor-set profiling protocol that grades every (oracle, task type, target family) cell into an evidence-backed capability map, feeding two deterministic gates — a DecisionGate that blocks actions lacking an evidentiary basis and a ClaimGate that downgrades claims exceeding it; the profile is the gate's evidence base. We first show that the failure modes CapGate counters are measurable defaults of the ungated system — three deployed structure oracles failed all 18 screening cells and an ungated agent issued false-positive claims at 54.5% (93.8% on untrusted-oracle tasks) on the 45-task audit set — and then that gating eliminates false claims on both flagship task families (gated 0% and 8.3% versus ungated 54.5% and 38.9%, both arms re-run at the reset scale) at a measured, decomposable true-positive cost (80% and 100% retention), with selective rather than prohibitive behaviour on certified oracles. CapGate is a production default of the platform: the profiled evidence is packaged with the system, managed oracle calls are gated at the single choke point every tool invocation passes, and every gate decision joins the audit trail.

4. **Generation-layer constraint navigation (GenNav).** A feasibility-first generator-navigation strategy that delivers batches of candidates satisfying pre-registered multi-constraint profiles — the regime where an agent demonstrates value beyond a single tool's native reach. GenNav succeeds decisively where a rule-based executor fails on full-length mRNA design (McNemar P = 1.9 × 10⁻⁹, discordant 30:0), and the identical machinery, transferred to a structure-guided aptamer generator with an entirely different control geometry, wins the discordant cells 14:3 at equal budget (McNemar P = 0.013) after lattice densification and starvation-free allocation — with the advantage's regime boundary established by a pre-registered confirmatory run. The decisive aptamer protocol ships with the platform as a user-selectable mode of the aptamer workflow: deterministic (zero LLM calls), budget-capped, and audited call-by-call like every other platform action.

## Results

### Overview of the RNADesignAgent platform

RNADesignAgent is organized as seven layers (Fig. 1a). At the base (L0), each of the 41 scientific tools — wrapping 20 vendored external research codes (17 registered git submodules) — runs in its own environment behind one of 21 local HTTP microservices, so that heavyweight GPU models (RhoFold, Protenix, EGARPS, ODesign), CPU optimizers (LinearDesign, LinearFold, ViennaRNA) and alignment suites (BLAST+, Bowtie2) are invoked through uniform, versioned contracts. Tool specifications (L0), capability wrappers that validate outputs and write per-call audit records (L1), and eleven domain workflows with a fixed generate → evaluate → score → rank skeleton (L2) are all deterministic; a service manager (L3) maps each workflow's declared requirements to microservices, health-checks them and auto-starts what is missing. Session memory and workspace management (L5) and the CLI/FastAPI entry façade (L6) complete the platform (Fig. 1c).

Two design commitments distinguish it (Fig. 1a, bottom). First, the LLM never writes sequences: its roles are restricted to orchestration, review and reporting, so every molecule traces to a deterministic generator call. Second, every comparative claim follows a pre-registered, budget-matched protocol, so reported effects are attributable to mechanisms rather than to sampling effort.

The multi-agent execution layer (L4; Fig. 1b) comprises four cooperating agents whose individual contributions we measured rather than assumed. A PipelineAgent schedules multi-node pipelines deterministically. Per-workflow SpecialistAgents own strategy and retry, deciding retries solely on hard failures (empty candidate sets, tool errors); workflows with heterogeneous multi-objective candidate pools (five of eleven: full-length mRNA, aptamer, siRNA, sgRNA, tertiary structure) rank candidates through a shared Achievement Scalarizing Function reference-point layer (Methods) — an earlier bounded coordination loop on top of this ranking showed an apparent coordination benefit that dissolved under budget-matched controls (see below) and was removed from the system. A QualityAgent reviews outputs against per-workflow quality profiles; it is advisory by governance — with and without it, all 19 tasks of the process-aware regression suite succeed, and by construction an LLM review failure can never convert a successful run into a failed one. A SynthesisAgent drafts multi-node reports, and its headline claims pass through the ClaimGate before publication. CapGate itself runs as a platform service rather than an experiment harness: the profiling evidence is packaged with the system as a default SelfModel, and a single choke point that every tool invocation passes records each call to the audit trail and blocks managed oracle calls whose evidentiary basis is absent — so the calibrated behaviour described in this paper is the system's out-of-the-box default, not a campaign-specific wrapper. This measured accounting of the multi-agent layer is, to our knowledge, the first in the scientific-agent literature where each agent's marginal contribution is reported, including negative results.

### RNADesignAgent executes eleven RNA design workflows with biologically valid outputs

We first established that the platform's outputs are biologically meaningful across all eleven workflows, using RNADesign-210 — our 210-task benchmark paired with designed null models and literature anchors (Figs. 1f and 2). Every task completed successfully (210/210; Fig. 2a). Five observations anchor biological validity (Fig. 2b–g). (1) On 20 wild-type protein targets, the CDSs delivered by the platform's default design flow — LinearDesign over its λ grid plus RNARL and GEMORNA, each generator designing against the target species' codon-usage table, every candidate folded, scored and ranked end-to-end — reached a median codon adaptation index (CAI) of 0.832, exceeding wild-type sequences (0.729; Mann–Whitney P = 6.9 × 10⁻⁴, Cliff's δ = 0.63), which themselves exceed random synonymous sequences (0.675, n = 200; P = 6.8 × 10⁻⁷, δ = 0.67): the platform reproduces the direction of natural selection on codon usage and improves on it, and the wild-type-over-random ordering certifies that the assay reports a biologically meaningful direction. The same delivered CDSs are simultaneously far more structured than either control (folding energy per nucleotide −0.336 versus −0.051 and −0.047; P ≤ 7 × 10⁻⁸, δ = −1.0 against both nulls), whereas wild-type and random sequences are indistinguishable on this metric (P = 0.29) — designed sequences therefore lead on codon adaptation and structure at once, and the CAI ordering is not a folding artefact of the nulls (Fig. 2b,c). These lifts are system-level properties: the designed sequences are the ranked deliverable of the platform's one-call, audited CDS workflow in its default configuration, with no objective tuning. (2) Inverse folding against target secondary structures recovered the exact target in 21 of 25 benchmarks (Fig. 2d); the four misses sit 2, 2, 4 and 6 dot-bracket positions away (1, 2, 3 and 1 base pairs on targets of 6–16 pairs), all on partition-function-mode, combined-parameter, 70 °C or 54-nucleotide edge cases, and in each miss no candidate in the ranked set was exact — the shortfall is generation-limited rather than ranking-limited. (3) On an expanded literature panel of internal ribosome entry sites — nine validated IRES 5′UTRs (six viral: EMCV, HCV, poliovirus, FMDV, HRV-A1 and BVDV-1; three cellular: c-myc, VEGF-A and Bip) against 50 random human 5′UTRs — scored threshold-free in the underlying oracle's native sliding-window regime, discrimination was limited and did not reach significance (AUROC 0.673, 95% CI 0.467–0.862, P = 0.102; Fig. 2e), and the workflow's default full-sequence path showed none (0.478, 0.311–0.649, P = 0.841); both sit below the 0.8 screening threshold that the capability profile assigns this oracle, so the measured negative is reported as such rather than tuned away. (4) On 22 siRNA design tasks, all but one delivered a best-ranked candidate with zero predicted off-targets (Fig. 2f); the sole exception, the bowtie2 identity-70 edge task, carried three predicted hits. Scan evidence is trace-verified rather than assumed: the two inputs that request a transcriptome scan both executed against the human GENCODE v46 reference (254,070 transcripts) — one BLAST search returning clean, one bowtie2 search returning the three hits — while the remaining twenty zeros are scan-skipped by input specification (nineteen disable the scan, one lacks a species reference). (5) The small-molecule binding oracle displayed the two-sided boundary its capability profile encodes (Fig. 2g): through the deployed service it reproduces its published held-out evaluations exactly (AUROC 0.974, 95% CI 0.968–0.980, n = 1,492 ROBIN pairs; 0.983, 0.961–0.997, n = 170 PDB pairs; the true ligand ranking 2nd of 1,601 and 7th of 265 in the two published decoy case studies), whereas short-aptamer panels outside the training distribution show no demonstrated power (0.722, 0.278–1.0 against random chemistry; 0.563, 0.063–1.0 against near-cognate ligands; both intervals spanning chance).

End-to-end, every campaign ships a complete per-tool-call audit trail: the 241-run timing campaign described below deposited 10,217 audit events — 8,798 tool calls (86.2%; 40 distinct tools; 6 failures, all within one session's recovered retry sequence), 1,377 gate decisions (13.5%; 690 reject, 553 require-profiling and 134 downgrade across 11 oracles) and 42 ranking-objective assemblies — and every event class resolves call-by-call in the representative three-turn full-length mRNA session (Fig. 2h; 152 calls, 32 gate decisions and 2 ranking assemblies over an 8.3-min audited span; case studies in Table 1). Full design campaigns complete in minutes to about an hour per target: across 241 timed end-to-end runs through the user form entry on the pre-warmed platform — all 210 benchmark tasks plus the 31 regression sessions — the pooled median runtime was 2.6 min, workflow medians spanned 2.5 s (deterministic mRNA scoring) to 6.3 min (aptamer design), 76.3% of runs finished within 5 min, 92.9% within 10 min and 240 of 241 within 1 h, the single exception being the constraint-navigation aptamer session at 98.6 min (Fig. 2i).

### Uncalibrated trust, claim overreach and confounded improvement are measurable defaults

Having a working platform made it tempting to treat its most sophisticated scorers as oracles for optimization. Here we show that this temptation is not survivable: uncalibrated scores corrupt an agent's actions, the language in which it reports them, and even its evidence of self-improvement — three failure modes that are measurable defaults of tool-using agents, each quantified on the live platform as shipped (Fig. 3).

**Uncalibrated tool trust.** We profiled the three structure-based oracles deployed in the aptamer workflow — EGARPS+ native probability, ProteinX ipTM and RhoFold mean pLDDT — on assertion-curated anchor sets: 95 sequence entries spanning nine protein targets (67 binders, 62 of them with a measured Kd, and 28 negatives; FGF2 contributes ten table-printed binders spanning 2.2 orders of Kd, swine influenza H3N2 HA four, and IFN-γ a six-member same-family series; two further surveyed targets failed sequence printability at the curation gate and were rejected), together with 19 RNA–protein complexes with solved native structures across 14 independent targets for docking (SOMAmer-class and mirror-image chemistries rejected at curation with verified reasons). Each (oracle, target) cell was graded against pre-registered thresholds for three capabilities — screening (binder-versus-negative AUROC > 0.8), ranking (Spearman ρ ≥ 0.6 against measured Kd) and docking (native pose top-1 in ≥ 2/3 of complexes) — and every measurement ran zero-intervention through the deployed RhoFold → ProteinX → EGARPS service chain as shipped (95/95 screening entries, 54/54 affinity-series entries and 397/399 docking poses scored; the two pose failures were reproducible service-side and are disclosed). No oracle showed reliable power in any capability. Screening (Fig. 3a): 2 of 27 oracle–target cells nominally exceed the gate — ProteinX on swine H3 HA (AUROC 0.83, 95% CI 0.33–1.0) and EGARPS on IFN-γ (0.83, 0.50–1.0) — both small-n cells, and all 27 bootstrap intervals cover chance; FGF2, the widest-Kd-span target, stays sub-gate for all three oracles (0.37, 0.63 and 0.30). Ranking (Fig. 3b): 4 of 27 cells nominally reach ρ ≥ 0.6 — all three oracles on the IFN-γ series (ρ = 0.71, 0.66 and 0.60, n = 6) and ProteinX on Angiopoietin-2 (ρ = 1.0, n = 3) — yet none survives scrutiny: the three IFN-γ intervals span zero and that series is a single in-silico-mutant family spanning under one order of magnitude of Kd (a within-family covariation regime registered at curation), while the Angiopoietin-2 estimate rests on three points whose scores flip between ~0 and ~1 across stochastic complex realizations. No oracle passes on more than one target.

Docking failed at scale (Fig. 3c): across the 19 complexes — the seeded rigid-body decoy protocol offline-calibrated, its contact computation reproducing the 1HVU native count of 152 exactly — the native pose ranked top-1 in 0 of 19, sitting at ranks 6–20 of 21 candidates and scoring below the median decoy in most complexes (the HIV-1 RT T1.1 native at 0.008 versus a decoy median of 0.34). An affinity-calibration panel returned the same verdict from the Kd side (Fig. 3d; 95/95 entries re-scored): the six-point thrombin Kd series reached ρ = 0.49, below the ranking gate, and pooled binder-versus-negative separation was at chance (AUROC 0.52, 95% CI 0.39–0.65; 62 binders versus 28 negatives). The one consistent pattern is per-entry inversion — the marketed drug pegaptanib scores ~1.3 × 10⁻⁶ while a scrambled TBA scores 0.98 — and all three score classes (binders, literature negatives and random sequences) span the full nine-order-of-magnitude score range with interleaved medians (0.22, 1.4 × 10⁻³ and 2.2 × 10⁻² respectively). The deployed oracle is therefore uncalibrated rather than reliably inverted: an agent optimizing against it would be climbing noise.

**Claim overreach.** Because agents narrate their results, the second failure mode enters through language (Fig. 3e). On a 45-task audit set of design-reporting tasks — the registered 20-task set carried byte-verbatim and extended by pre-registered construction rules across all nine anchor targets — an ungated agent (same prompts, same underlying LLM, exactly two calls per task, oracle scores fetched live from the deployed services) issued false-positive claims at a rate of 54.5% (30 of 55 claims, 95% CI 41.5–67.0%), and its plans or statements exceeded the scope the evidence sanctioned 59 times, spread 8–11 per oracle-and-use cell. The failure is class-selective: the 24 trusted-deterministic tasks produced 23 claims, every one verified true by exact recomputation, whereas on the 21 untrusted-oracle tasks whose scores come from the structure oracles profiled above, 30 of 32 claims were false (93.8%; ranking 16/17, screening 9/10) — the agent names an oracle's top scorer as the best binder, which the withheld Kd ground truth contradicts. The two task strata measure the same rate (legacy 55.6%, extension 53.6%).

Profiling is equally able to *certify* power where it exists, which is what makes the capability map a usable self-model rather than a list of prohibitions (Fig. 3f). The full-length mRNA workflow's expression oracle — the GEMORNA 5′UTR mean-ribosome-load (MRL) predictor — passed decisively on all three anchor families curated from a published massively parallel translation assay (706 anchors; Sample et al., GSE114002): the random 50-nt family lies inside the oracle's training distribution and serves as the registered positive control, and the two varying-length families carry the generalization evidence. Screening AUROC reached 0.990, 1.000 and 1.000 across the three families with bootstrap intervals clearing the 0.8 gate, and ranking ρ reached 0.926, 0.920 and 0.835 against measured MRL with intervals (0.75–0.95) entirely above the 0.6 gate — 706/706 anchors scored zero-intervention through the production tool path, the oracle deterministic end-to-end through the deployed chain. The same audit classified the platform's 3′UTR stability predictor as unprofiled — no measured-stability anchor set exists — and the DecisionGate accordingly blocks any ranking action that would rely on it.

Profiling the *deployed* artifact rather than trusting the publication proved just as essential (Fig. 3g). The small-molecule oracle RNAsmol had initially failed to reproduce its own published performance on its own held-out test splits — a degradation with no error signal that only deployed-artifact profiling caught. Recovered byte-verbatim from version control and re-measured in an isolated sandbox on the same 1,662 official pairs, the pre-fix service scores AUROC 0.790 and 0.420 on the two splits (n = 1,492 and 170), agreeing with the registered incident record within 0.009. Git archaeology showed that its preprocessing carried two deviations from upstream: the model's case-sensitive RNA encoding (lowercase denoting modified bases) was collapsed to uppercase, and an upstream indexing quirk in the molecular-graph adjacency — on which the shipped checkpoints were trained — had been "corrected" into a full symmetric matrix. After the preprocessing repair, both shipped integration paths were verified live and zero-intervention on the same pairs: the default agent tool path (wrapper uppercase + T→U normalization, verified applied on every pair) reaches 0.975 and 0.986, and the verbatim service endpoint 0.974 and 0.983, the latter bit-identical to the registered evidence. These three measurements close the defect decomposition — and they falsified our own pre-registered expectation that agent-side normalization alone would reproduce the collapse: collapsing case perturbs individual scores substantially (PDB split median |Δp| = 0.08, maximum 0.91) yet leaves in-distribution discrimination intact, so the damage lived in the adjacency rewrite, not in case information. The deviation that looked obviously fatal was harmless; the deviation that looked like an improvement destroyed the oracle. Deployment infidelity is real, silent and layer-dependent, and which layer carries it is an empirical question that only measurement answers.

**Confounded improvement.** The third failure mode we found in our own earlier results (Fig. 3h). RNADesignAgent's bounded coordination loop — a deterministic, rule-based multi-round expansion that we removed from the platform once its gain was falsified — is here reconstructed verbatim at the experiment-driver level as the object of study and run against the production tool path across the full aptamer benchmark (20 targets × 3 seed sets × 4 arms = 240 cells; 228 successful, the Ferritin zero-output boundary being the registered exclusion, leaving 56 paired (target, seed) cells over 19 effective targets). The four arms are the loop itself, the serial baseline, a budget-matched one-pass serial arm and a fixed-resampling control in which the loop's between-round diagnosis is replaced by a content-free regeneration instruction. On the EGARPS-component best-of-pool metric — precisely the oracle that profiling decertified — the loop's apparent advantage over the serial baseline is directionally positive and nominally significant (Cliff's δ = +0.14, paired Wilcoxon P = 2.6 × 10⁻³, 41 of 56 cells; permutation-null P = 0.06), yet already below the pre-registered effect-size gate (δ ≥ 0.3), because each coordination round doubles the evaluated pool. The two pre-registered controls dissolve it: under budget matching the advantage falls to δ = +0.05 (P = 0.21), and replacing the diagnostic content with fixed resampling at identical mechanics and budget leaves exactly nothing (δ = −0.01, P = 0.73). A formal self-audit of our two strongest legacy claims under the four-step protocol — declare capability dependencies, re-check against profiles, control confounds, gated re-adjudication — retired both (claim survival 0 of 2 against a pre-registered 70% threshold). We treat budget matching as an iron rule for every comparative claim in this paper.

### Capability gating eliminates false claims while preserving true ones

The remedy for uncalibrated trust and claim overreach is CapGate: a deterministic two-layer gate fed by the capability self-model (Fig. 1d). The DecisionGate intercepts planned actions and forbids those whose evidentiary basis is absent from the self-model — for example, ranking candidates by an oracle with no measured ranking power. The ClaimGate intercepts outgoing natural-language claims and downgrades them along a scope ladder (absolute → same-target relative → trend-only → suppressed), enforcing "no claim without verification". Both gates are deterministic, and every decision is appended to an audit trail, so the agent's epistemic behaviour is itself auditable. CapGate governed every comparative campaign reported in this paper, and it is now the platform's production default: the profiling evidence is packaged with the system, managed oracle calls are gated at the tool-execution choke point, and unprofiled predictors are blocked by default pending evidence (Fig. 4f).

We evaluated CapGate under two arms with identical prompts and the same underlying LLM, with claims adjudicated blind to arm by a deterministic adjudicator. Both arms were re-run under the programme reset on the 45-task aptamer-chain and synthetic audit set (24 trusted-deterministic tasks with exactly recomputable ground truth; 21 untrusted-oracle ranking and screening tasks over the nine-target anchor set). Gating reduced the false-positive claim rate from 54.5% (30/55; 95% CI 41.5–67.0) to 0% (0/31; CI 0–16.1) and decision-layer overreach events from 59 to zero (Fig. 4a,b) — a hard guarantee of the gates rather than a statistical outcome, and it held on every task. True-positive retention was 80.0% (25 → 20), below our pre-registered 90% retention gate, and the losses decompose deterministically: two true metric claims were suppressed by the uniform basis rule (the model declared the deterministic metric itself as an evidentiary dependency, which gates as unprofiled — over-conservative, and a real cost of closing the free-proxy back door); two length-sloppy final sequences were abstained by the execution-verification leg and would have been false positives had they been published (the ungated arm had simply emitted clean sequences there); and the ungated arm's two true positives on untrusted-oracle tasks were lucky correct picks that the gated arm cannot retain by design, because no structural oracle holds verified ranking or screening power and unverifiable comparative claims are exactly what the gates forbid. Conversely, one true positive was rescued on a task where the ungated arm had made none. The mechanism is abstention and suppression, not silence: the gated arm issued 31 claims, of which 24 were published (20 adjudicated true, 4 borderline trend statements) and 7 suppressed at the claim gate. A pilot of this experiment had initially failed because the LLM, when blocked, substituted an undeclared free proxy — a protocol lesson now encoded in the pre-registration template: gating must close all unverified claim paths. To test generality on the second flagship family, we built a 20-task mRNA-side audit set (E3-M) from real full-length design-reporting tasks — ten with exactly recomputable ground truth (CAI, folding energy, constraint satisfaction) and ten whose evidence basis the profile denies or degrades. Gating reduced the false-positive rate from 38.9% (7/18) to 8.3% (1/12) with true-positive retention of 100% (11/11) and zero gated overreach events (Fig. 4d); the one surviving false positive traces to a predicted-versus-measured MRL rank flip on the weakest certified family (ρ = 0.835), a ground-truth property both arms face symmetrically.

On certified oracles the gates are selective rather than prohibitive (Fig. 4e): ranking by the MRL oracle is permitted on the families where profiling certified it, transferred only with decayed confidence to never-profiled families of the same oracle, and blocked outright for the unprofiled 3′UTR stability predictor. The governance result closes the loop (Fig. 4g): quality review is advisory (19/19 with and without), and an LLM review failure — for example, an API outage — is recorded as audit metadata that can never convert a successful run into a failed one. Across every campaign the in-system LLM footprint stays minimal by construction — two calls per task in the gating experiments, 2.4 per gene in mRNA navigation, a single call across the decisive aptamer run (Fig. 4h).

### Generation-layer constraint navigation delivers pre-registered design profiles

Where can an agent demonstrate value beyond a single tool's native reach? Single-metric quality (CAI, folding energy) is essentially determined by the generator's settings; within that range an agent adds nothing. The defensible agent task — arrived at through a failed experiment — is *multi-constraint batch delivery*: per target, a ranked batch of candidates jointly satisfying a pre-registered constraint matrix across multiple design profiles. GenNav implements this at the generation layer (Fig. 1e): a feasibility-first adaptive probe over the generator's control lattice (LinearDesign λ settings for mRNA; ODesign length–seed–sample gears for aptamers) establishes which gears are feasible per target before budget allocation; profile-orthogonal generation axes make design profiles separable by construction; a diversity expander enforces minimum pairwise distance within batches; and an explicit degrade path handles targets with no feasible operating point.

A first attempt had placed navigation in the selection layer — filter and rank a fixed 315-candidate pool — and failed its diversity gates for reasons structural to the generation layer: admissible candidates saturated a single λ setting (insulin batch diversity 0.82% against a 2% requirement) and feasible-gear coverage collapsed on GFP until a species-matched *E. coli* codon table was supplied (pool pass 0/315 → 12/315; Fig. 5a). Sinking navigation into the generation layer fixed exactly these failures. On 18 mRNA targets under pre-registered dual endpoints, GenNav met the primary endpoint decisively: per-profile joint-criteria delivery passed for the gated navigation arm and failed for the rule-based arm in all 30 discordant pairs (McNemar P = 1.9 × 10⁻⁹, n = 54 = 18 targets × 3 profiles), with gene-level end-to-end delivery at 1.0 (Fig. 5b,c). The stricter secondary quality bundle did not pass and is disclosed rather than hidden: essentially all quality failures trace to a single target, HER2, for which the feasibility probe found no feasible λ gear and the system degraded gracefully by design. Total LLM usage was 43 calls (mean 2.4 per gene), below the pre-registered budget (Fig. 5d).

To test generality beyond codon space, we ported GenNav — unchanged in mechanism — to the aptamer workflow, where post-profiling no structure oracle may rank candidates and the generator exposes an entirely different gear geometry. The campaign arc (Fig. 5e–h) is itself a result about where navigation earns its keep. The initial transfer (E8) confirmed mechanical generality — the navigator repaired every rule-based delivery failure it met, delivered end-to-end on 9 of 10 targets against the rule arm's 7, and spent fewer candidates (mean 36 versus 48) — but the primary endpoint was not met: 26 of 30 profile pairs pass under both arms, so no advantage can be demonstrated where the static grid already suffices, the same saturation logic that retired the selection-layer campaign. Re-anchoring the constraint matrix to make delivery gear-scarce raised rule-arm failures from 3/30 to 11/30 and exposed the real boundary; three pre-registered levers then converted the boundary into an advantage at identical 48-candidate budget: a densified 17-length lattice and S1-measured priors improved discordance fourfold (9:2, P = 0.065), and a deterministic guaranteed-repair allocation — one reinforcement round for every repairable band before any band receives a second — eliminated the per-band starvation that had repeatedly cost single cells. The decisive campaign (E14; 12 targets, panel chosen by a pre-registered rule) won the discordant cells 14:3 (McNemar P = 0.0127, n = 36): the navigator delivered 26 of 36 profile cells against the static grid's 15 (72% versus 42%), completed end-to-end delivery on 6 of 12 targets against none, never violated a budget or gate, and required a single LLM call across the entire run — the guarantee rounds are deterministic. A pre-registered confirmatory run (E15) on never-paneled targets kept the discordant wins at 14 but conceded six cells (P = 0.115; pooled across campaigns 28:9, P = 0.003, heterogeneity acknowledged), empirically confirming that the navigator's advantage is regime-specific to delivery-scarce panels. Navigation earns its keep where the generation layer makes delivery hard — codon-objective trade-offs on mRNA, scarce-band allocation on aptamers — and the honest outcome outside that regime, or where no feasible operating point exists, is a declared degradation rather than a silently weaker delivery. The decisive protocol ships with the platform as a user-selectable mode of the aptamer workflow (deterministic, budget-capped, audited call-by-call).

### Pre-registered negative results delineate durable boundaries

Three boundary findings survive as scientific results in their own right (Fig. 6). First, junction repair has no free lunch (Fig. 6b): three independent pre-registered attempts to repair 5′UTR–CDS junction burial — post-hoc codon shuffling with a stability-weight sweep, a junction-penalized global-fold optimizer (a purpose-built LinearDesign patch), and a generate-and-select route against a validated full-length constrained-fold ddG metric — all failed their acceptance gates because opening junctions costs global stability. The ddG metric itself passed validation (constraint obedience 216/216; LinearFold-versus-ViennaRNA r = 0.945; Fig. 6c) and is now the platform's reporter; we regard this triple of negative results as a durable contribution to the mRNA design community. Second, cross-campaign memory does not pay (Fig. 6d): a 120-campaign trial of experience injection cut evaluation budgets by 74.2% (814 versus 3,153 evaluations) but produced no learning-curve improvement (all three seed-group slopes positive; P = 0.91) and no design-quality gain — the strategy was abandoned and the negative result registered to discourage repetition. Third, the generator boundaries themselves (Fig. 6e): ODesign produces zero candidates on a ferritin-family target class, LinearDesign has a hard memory ceiling on multi-thousand-amino-acid proteins (now fail-fast under an address-space guard), and HER2-class targets admit no feasible λ gear — exactly the kind of tool limits a calibrated agent must know before, not after, planning a campaign. Together with the capability map (Fig. 6a), the closed escape routes around the budget rule (Fig. 6g), the classified failure taxonomy of all campaigns (Fig. 6h), the per-campaign LLM usage accounting (Fig. 6i) and the aptamer scarcity boundary (Fig. 6f), these results define what the agent may not claim as firmly as the earlier sections define what it may.

## Discussion

In this work we showed that three failure modes of agentic science — uncalibrated tool trust, claim overreach and confounded improvement — are not theoretical risks but measurable defaults of a deployed system, and then presented RNADesignAgent, a tool-first agent built to counter them. Three findings carry the argument. First, capability profiling revoked every presumed oracle power we tested on the aptamer chain — on the reset's expanded panels no screening cell is reliable (2/27 nominal passes, both small-n with confidence intervals covering chance), no ranking cell is reliable (4/27 nominal passes, all vacuous) and docking fails in 0/19 complexes — while certifying power where it genuinely exists — the expression oracle's ranking power on measured-MRL anchors, and a small-molecule oracle's published performance, reproduced exactly once a silent deployment fault was repaired. Profiling is a two-sided instrument: it tells an agent not only what it may not do, but what it may. Second, budget-matched self-audit retired our own headline claims, showing that confounded improvement is likewise a default state of agentic evaluation. Third, the remedies work: capability gating eliminated false claims while preserving true ones on both flagship task families, and generation-layer constraint navigation delivered pre-registered multi-constraint profiles with decisive significance on mRNA (McNemar P = 1.9 × 10⁻⁹) at 2.4 LLM calls per gene — and the identical machinery, re-pointed at a generator with an entirely different gear geometry, won the discordant cells 14:3 on aptamers at equal budget with a single LLM call across the run.

A central insight is that the locus of intelligence in a trustworthy agent is not the language model but the *evidence infrastructure* around it: the anchor sets, the capability grades, the gates, the audit trail. This is a principled response to how agentic systems actually fail: language is where overreach enters, so claims — not just actions — must be gated; sampling is where confounds enter, so budgets — not just outcomes — must be controlled; and deployment is where tools silently diverge from their papers, so the deployed artifact — not the publication — must be profiled. The multi-agent layer follows the same discipline: each agent's contribution is measured, and where measurement falsified a benefit — coordination, cross-campaign memory — the mechanism was demoted to what the evidence supports. We also note what calibrated agency is not. It is not autonomous discovery: the system is a scientist-in-the-loop design instrument whose deliverables are candidates, profiles and audit trails, and we emphasize the distinction between calibrated tool orchestration and genuine scientific reasoning. Nor is it a claim that the underlying oracles are weak — only that their power is regime-specific, and that the regime must be established before, not after, optimization. Finally, because RNA design touches therapeutic development, dual-use considerations apply: the platform's deterministic gates, off-target scanning and per-call audit trails are guardrails in themselves, and we release the capability map so that others can inherit the boundaries rather than rediscover them.

Several limitations mark opportunities for continued development. (1) All validation is computational; the anchors and nulls are literature-derived, and no wet-lab confirmation was performed. The profiling protocol, however, is wet-lab-ready: anchor sets accept new measurements as first-class rows, and capability grades update without code changes. (2) A single LLM backend (DeepSeek) was used for the in-system language roles. Multi-backend replication was descoped by decision: the gated roles are narrow (tie arbitration, claim drafting), the gates themselves are deterministic and model-agnostic by construction, and the result that quality review is advisory-only (19/19 with and without) bounds the backend's influence on outcomes. (3) Capability profiles currently cover the oracle families used for selection and ranking in the two flagship task families; the platform's remaining predictors carry only their literature validation until profiled, and the anchor sets, though assertion-curated and coverage-checked, remain modest in size. Under the production enforce policy this means aptamer structure-oracle components default to zero for all candidates equally — ranking then rests on the deterministic constraint matrix, which is the calibrated behaviour — but richer oracle coverage would restore more informative ranking where power genuinely exists. (4) The rule-based comparator in the navigation experiments is deliberately simple; the discordance should be read as evidence that constraint navigation is necessary, not that every alternative heuristic would fail. (5) Navigation quality bundles fail on targets with no feasible generator operating point (HER2 class); expanding the generator family or the λ lattice for such targets is the next methodological step. Overall, these represent areas for ongoing development rather than fundamental limitations.

More broadly, the artifacts released here — the capability map of widely used RNA oracles, the assertion-curated anchor sets, the budget-matched pre-registration templates, and the register of concluded directions (including the junction-repair and memory-strategy negative results) — are reusable independently of our system. Any agentic pipeline, in any domain, can adopt the same discipline: profile before you optimize, gate before you claim, match budgets before you compare. We anticipate that calibrated agency will become more, not less, important as agents grow more capable, because each added capability enlarges the space of plausible-sounding but unverified actions.

## Methods

### System architecture

RNADesignAgent is implemented as seven layers. L0 (tools): 41 scientific tools, each defined by a Pydantic-typed specification (identity, version, endpoint, capabilities, limitations) and exposed through one of 21 local FastAPI microservices, one per external code family, each with its own environment and local model weights; 20 external research codes are vendored under `external_repos/` (17 registered git submodules). L1 (capabilities): thin wrappers that validate tool outputs against their specifications and write audit records (unique per-parameter result keys, per-call timings) into the shared state. L2 (workflows): eleven domain workflows (mRNA CDS design, full-length mRNA design, mRNA sequence scoring, siRNA design, sgRNA design, ASO target screening, IRES prediction, RNA aptamer design, RNA secondary-structure design, RNA tertiary-structure design, RNA–small-molecule interaction), all subclasses of a base workflow enforcing a generate → evaluate → score → rank skeleton with progress events and partial-rerun support. L3 (service orchestration): a service manager mapping each workflow's declared `required_capabilities` to microservices, with file-locked, health-check-gated auto-start. L4 (multi-agent execution): a deterministic PipelineAgent scheduling pipeline nodes; per-workflow SpecialistAgents owning retry decisions (hard failures only); the five multi-objective workflows rank through the shared ASF reference-point layer described below (a bounded coordination loop formerly layered on top was evaluated, not credited with a coordination benefit, and removed — Results); an advisory QualityAgent issuing per-workflow quality reports (three deterministic workflows are explicitly exempt); and a SynthesisAgent for multi-node reports. L5 (session/workspace): per-session workspaces with context-propagated session IDs and cross-turn result history. L6 (entry): a form-driven CLI and FastAPI façade through a unified runner; workflow selection is explicit, and user-supplied parameters are sanitized against workflow input models.

### Multi-agent execution and governance

Each agent's role is deliberately narrow, and each claim about it is measured. The SpecialistAgent retries only on `WorkflowResult.is_hard_failure` (success = false with empty candidates or tool errors). The QualityAgent produces advisory `QualityReport`s; if the LLM review call fails, the report is marked `review_unavailable` (zero-confidence pass) with the error retained in state for audit, and an LLM-chosen abort is recorded as advice only — neither path can flip a successful run to failed (verified 19/19 on the process-aware regression suite, both arms). The former BMC coordination loop was evaluated under budget-matched and guided-versus-unguided controls, registered in the project's decision log, and removed from the implementation after its control showed statistical parity with plain serial generation. Mechanized ranking replaces LLM ranking outright in the navigation campaigns: the system enforces utility order and the LLM arbitrates ties only (Kendall τ = 1.0 versus system order at three calls per campaign).

### Candidate ranking: achievement scalarizing reference-point optimization

Every workflow whose candidate pool carries two or more heterogeneous objectives ranks through one shared implementation (`agent_core/workflows/multi_objective.py`). Objectives are min–max normalized to [0, 1] within the candidate pool, and candidates are ordered by an augmented Chebyshev achievement scalarizing function (ASF) against a reference point *r*: ASF(s) = max_i {w_i (r_i − s_i)} + ρ Σ_i |w_i (r_i − s_i)| with ρ = 10⁻³, which guarantees Pareto-optimality of the minimizer; weights are uniform by default or renormalized from a workflow's existing weight parameters. The reference point is user-supplied in raw units or, by default, the utopian point (pool-best per dimension); a non-dominated Pareto frontier on raw objective values is always returned alongside the ordering. The layer encodes three explicit missing-data policies. A dimension unmeasured across the whole pool — an oracle blocked by CapGate, or an optional evaluator disabled — drops out of the ranking for every candidate equally (the CapGate degrade semantics: components zero or vanish for all, never for some). A dimension missing for an individual candidate (a failed or skipped oracle call) is imputed at the measured pool-worst normalized value: omission from the Chebyshev maximum can only lower a candidate's ASF, so a 2026-08-20 audit replaced the earlier omission semantics — which rewarded evaluation failures — with pool-worst imputation, which additionally leaves the normalization of the measured candidates undistorted. A user reference point covering only part of the measurable dimensions restricts the ranking to that subset and is flagged in the run summary rather than applied silently. Five of the eleven workflows use this layer — full-length mRNA (CDS quality, 5′UTR ribosome load, 3′UTR stability, full-length folding energy), aptamer (complex probability, predicted fold confidence, interface score), siRNA (duplex efficiency, specificity, and a nearest-neighbour thermodynamic end asymmetry that favours antisense-strand guide loading; the full pool is ranked before truncating to the requested count), sgRNA handle (CRGPT perplexity, CRISOT specificity) and tertiary structure (predicted fold confidence plus two reference-based closeness measures, RMSD and TM-score); the remaining six are single-objective, single-candidate or domain-formula tasks where scalarization is vacuous and rank directly. ASF values are pool-relative by construction (ranks are non-monotonic under pool composition, and the utopian reference can be attained, ASF = 0); cross-pool comparisons therefore never compare raw ASF distances — they use shared fixed reference points, per-objective components or Pareto hypervolume.

### Capability-layer evidence gating (CapGate)

The SelfModel maps each (oracle, task type, target family) tuple to one of four capability grades (screening / ranking / docking / none) with evidence pointers and confidence. The CapabilityProfiler computes grades from anchor-set evaluations against pre-registered thresholds (screening AUROC > 0.8; ranking Spearman ρ ≥ 0.6; docking native top-1 in ≥ 2/3 cases), with a deterministic driver backend. The DecisionGate intercepts planned actions and forbids those whose evidentiary basis is absent; the ClaimGate intercepts outgoing claims and downgrades them along a scope ladder (absolute → same-target relative → trend-only → suppressed), enforcing "no claim without verification". Both gates are deterministic; every decision is appended to an append-only JSONL audit trail. Since the 2026-08-18 platform integration, CapGate is a production default rather than a campaign harness: a process-wide runtime (`agent_core/calibrated/runtime.py`) configured by the entry runner (environment switch `RNADA_CAPGATE` = off / advisory / enforce, default enforce) (i) records every tool call made by any workflow to the platform audit trail (name, arguments summary, success, timing, error, gate flag, and the session and workflow identity of the run that made the call, so every line of the append-only trail is attributable to its run), (ii) reviews the managed oracle tools — the aptamer structure oracles, both GEMORNA UTR predictors and the small-molecule scorer — against the SelfModel at the single tool-execution choke point, blocking calls whose grade is failed or unprofiled under enforce policy (workflows' existing fallbacks zero the affected component for all candidates equally, so runs complete and the oracle is neutralized rather than crashing), and (iii) passes the headline claims of multi-node synthesis reports through the ClaimGate, with claim extraction as the only LLM step. The profiling evidence travels with the system as a packaged default SelfModel built from the frozen E1, E7 and RNAsmol verdict files (generator `experiments/build_default_self_model.py`), so production gating enforces the published profiling results out of the box. Family transfer in the SelfModel is conservative: a never-profiled (oracle, task) family inherits the donors' worst grade per capability. Anchor sets are assertion-curated: entries carry role labels (binder, negative, unrankable), internal consistency assertions and negative assertions are checked at build time, and coverage (≥ 4 binders and ≥ 3 negatives per target) is verified before use. mRNA-side anchors follow the same pattern with measured continuous labels (mean ribosome load) substituted for affinities, dichotomized at pre-registered pool extremes (top versus bottom 60 of the read-depth-filtered pool) for the screening grade, with a 120-anchor rank-stratified subset per family for the ranking grade.

### Generation-layer constraint navigation (GenNav)

GenNav comprises four components: (1) a feasibility-first adaptive probe over the generator's gear lattice that determines which gears are feasible for a target before budget allocation, with an explicit degrade path when no gear is feasible; (2) profile-orthogonal generation axes so that design profiles are separable by construction; (3) a diversity expander enforcing a minimum pairwise edit distance within delivered batches; and (4) explicit generator-context resolution (for mRNA, species-matched codon tables; for aptamers, length and seed gears). Ranking is mechanized: the system enforces utility order and the LLM arbitrates ties only. Constraint matrices are pre-registered per campaign (mRNA matrix: GC content windows, homopolymer runs < 14 bp, initiation-region stems ≤ 12 bp, full-length stems ≤ 30 bp, boundary GC, CAI ≥ 0.8; aptamer matrix v3: per-profile length bands compact 25–34 / standard 40–55 / extended 61–80 nt, per-band GC windows and stem caps, homopolymer runs < 6 nt, and a within-batch normalized edit distance ≥ 0.15 among the five delivered candidates per profile). For mRNA, the gear lattice is the LinearDesign λ set {0, 2, 8, 20, 50} with profile-orthogonal axes (CAI-maximizing, fractional, floor); for aptamers, the lattice is the ODesign (length, seed, sample-count) grid over a densified 17-length lattice (~3 nt per band: {25, 28, 31, 34, 40, 43, 46, 49, 52, 55, 61, 64, 67, 70, 73, 76, 80}). The generation budget is identical across arms in every campaign (the budget-matching rule): on aptamers, 48 raw candidates per target per arm, the navigation arm spending at most four targeted reinforcement rounds of six candidates inside the same cap, with a deterministic guarantee rule that allocates one round to every repairable delivery band before any band receives a second. Reinforcement gears are selected from S1-measured laplace-smoothed pass rates (S1 probe: the same lattice at depth two per length); the S2 allocation fuses the S1 prior with the live pool at no extra budget. Aptamer target metadata are assertion-checked before generation: a target's declared hotspot residues are validated against the structure chain's numbering, falling back to automatic hotspot identification on mismatch. Since the 2026-08-19 platform release, the decisive aptamer protocol is a production path: the aptamer workflow's opt-in navigation mode runs the densified-lattice probe, the cycling guaranteed-repair allocation and the per-profile delivery deterministically (zero LLM calls), folds every candidate through the audited LinearFold service for the constraint matrix, caps the generation budget at 48 raw candidates, stops early once every profile is deliverable, and writes the complete navigation trace (probe, rounds, per-profile deliveries, degrades) to the run record — so a navigation campaign is reproducible from its audit trail exactly like every other platform action.

### Benchmarks, anchors and experimental campaigns

Benchmarks used: a 210-task platform suite across the eleven workflows; a 20-target full-length mRNA suite (two legacy oversized targets — the ZIKV polyprotein and factor VIII, both beyond the LinearDesign memory guard — replaced by OTC, 354 aa, and PDGFB, 241 aa, with translation-verified RefSeq CDSs); a 20-target aptamer suite; and a 19-task process-aware multi-turn regression suite (also serving as CI). External anchors include BNT162b2/mRNA-1273 full-length sequences, 20 wild-type CDSs with 200 random synonymous controls, known aptamers (TBA, pegaptanib, SARS-CoV-2 N binders), an IRES positive/negative panel, small-molecule binder/non-binder pairs, RNAsmol held-out test splits and decoy case studies, and measured-MRL 5′UTR sets (Sample et al., GEO GSE114002). All comparative experiments followed the pilot-first protocol: pre-registration (hypothesis, primary metric, expected effect size, gate, pilot n recorded in the driver), a small-scale pilot with a decisive control arm, a go/no-go gate, and disciplined recording of negative pilots as evidence. The budget-matching rule — equal total generated-and-evaluated candidates across arms for any best-of-pool or hypervolume comparison — was enforced in P0, P3, E4, E6 and E8–E15. The E3 audit set was extended at the 2026-08-29 reset to 45 tasks — 24 trusted-deterministic and 21 untrusted-oracle spanning all nine anchor targets, the legacy 20 tasks carried byte-verbatim, construction rules pre-registered and assertion-checked, oracle scores fetched live from the deployed services. The gated treatment arm was re-run 2026-08-31 (Exp 17) on the identical 45 tasks through the production gate stack (SelfModel + DecisionGate + ClaimGate under enforce; plan requests gated per declared use at the oracles' registered task key; execution verification by exact recomputation before publication; ClaimGate suppression of unverifiable claims), paired task-for-task with the ungated control arm and adjudicated blind to arm. The E7 MRL certification was re-run the same day at 706/706 through the production tool path (advisory CapGate, zero LLM). The E3-M mRNA audit set mirrors the E3 construction on real mRNA assets: ten trusted-deterministic tasks whose ground truth is computed by exact recomputation (CAI via Sharp–Li weights on the built-in Homo sapiens Kazusa table; folding energy via LinearFold; constraint satisfaction) and ten untrusted-oracle tasks whose decoy scores are real platform outputs (GEMORNA 3′UTR stability and MRL on never-profiled families; junction metric). The gated arm's SelfModel is preloaded from the E7 profile, with deterministic report metrics registered per task family; both arms make exactly two LLM calls per task at temperature 0. The complete campaign-level evidence trail (pre-registrations, verdict files, adjudication materials, failure taxonomy) is bundled in `experiments/results/` and indexed in `docs/PAPER_FACT_SHEET.md`.

### Statistics

Paired comparisons used two-sided Wilcoxon signed-rank tests with Cliff's δ as effect size; multiple-testing control used Benjamini–Hochberg FDR. AUROC confidence intervals used 10,000-fold bootstrap. The GenNav primary endpoints used paired McNemar tests on per-profile joint-criteria pass/fail (mRNA: n = 54 pairs; aptamer: n = 30 pairs in the initial transfer, n = 36 pairs = 12 targets × 3 profiles in the decisive campaign). Oracle ranking grades used Spearman correlation against measured values (Kd or MRL). The memory learning-curve endpoint used a one-sided one-sample t-test on per-seed-group slopes. Thresholds were pre-registered per campaign (for example, δ ≥ 0.3 for pilot GO gates; AUROC > 0.8; ρ ≥ 0.6; FDR q < 0.05 with |δ| ≥ 0.3 for design gains).

### LLM usage and cost reporting

The sole external LLM in all reported results is DeepSeek (deepseek-v4-pro; official endpoint; temperature 0.2 for legacy quality reviews, 0.0 for the in-system LLM under test). Measured usages: platform quality-review suite 93 calls (414,088 prompt + 194,261 completion tokens); gating experiments 80 calls (legacy E3 register), 90 calls (Exp 17 gated arm, 45 tasks × 2) and two calls per task (E3-M); memory campaign 230 calls; mRNA navigation campaigns 3 (S0), 23 (S1) and 43 (S2) calls; aptamer navigation campaigns 76 calls total across E8 (mean 4.6 per target at S2) and a single LLM call across the 12-target E14 decisive run (deterministic guarantee allocation); oracle profiling campaigns use no LLM calls. All structure and sequence models run as local microservices with local weights. Experiment orchestration was assisted by a coding agent external to the tested system.
