## 1. 结论摘要

本系统（RNADesignAgent）的工作流是确定性工具管线。**全部实验结果中，唯一的外部 LLM API 调用是 QualityAgent 的质量评审**，全部走 **DeepSeek**：

| 项 | 值 |
|---|---|
| Provider | DeepSeek |
| Endpoint | `https://api.deepseek.com`（官方 API，经 `DEEPSEEK_BASE_URL` 配置） |
| Model | **`deepseek-v4-pro`**（经 `DEEPSEEK_MODEL` 配置；`rna_agent_system/.env` 实测值） |
| 角色 | `QualityAgent.review()`（每个被评审工作流运行 1 次，temp 0.2，约 3–4k tokens 入 / ~0.5k 出，见 MANUSCRIPT §1.4） |
| 其他 LLM 触点 | `SynthesisAgent`（仅多节点管线触发；本战役所有运行均为单节点/显式工作流，**未触发**）；规划/路由/BMC 协调/重试门控全部为规则逻辑，**无 LLM 调用** |

**除上表外没有任何外部 LLM API 参与结果产生**（例外：2026-08-04 E3 试点起，新 calibrated 栈的 LLM 规划/报告阶段作为**被测对象**进入实验数据，见 §2 末行——旧论文图 2–7 与 E1/P0–P3/P1 v2 的结论不受影响）：所有结构/序列模型（RhoFold、Protenix(ProteinX)、EGARPS、LinearDesign、GEMORNA、RNARL、RNASTOP、IRESfinder、EVITAR、CRGPT/CRISOT、RiboDiffusion、RhoDesign、RNAsmol、GerNA-Bind）与序列分析工具（ViennaRNA、LinearFold、Bowtie2、BLAST、codonw/CAI 表）均为**本地部署的微服务 + 本地权重**，不经过任何外部 API。

## 6. 以后实验的记录规范（强制）

1. **任何产生论文数据的实验，其驱动必须在运行记录中写明每个 LLM 调用的 provider / model / endpoint**（参照 `run_llm_backend_comparison.py` 的 `provider`/`model` 记录字段）；启用 token usage 采集（LangChain `response_metadata["token_usage"]` / `usage_metadata`），采集不到时在记录里写 `usage_available=false` 并用 §1 剖面估算。
2. 每个实验完成（或换模型/换端点）后，**当天更新本文件**：在 §2 表加行、在 §3 更新实测 token。
3. 切换 provider/model 只能经 `llm_config` 的环境变量或构造注入，禁止在代码里硬编码模型名；换模型后按 §2 重跑受影响实验并更新本文件。
4. 名义臂与实际端点不一致时（如 relay 不服务该模型），**禁止把 relay 模型标记为名目后端**；失败记录须注明"端点错配"（先例：2026-07-27 claude 臂 404，见 `run_llm_backend_comparison.py::BACKENDS` NOTE）。
